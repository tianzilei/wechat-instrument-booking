# 仪器预约小程序

一套基于微信小程序和微信云开发的仪器预约系统，支持公开周历查看、课题管理、注册审核、多时段预约、特殊时段审批、候补、规则复审、维护管理、隐私合规、数据生命周期、管理员治理和使用统计。

## 功能

- 公开周历查看所有预约占用情况，未登录用户也可以浏览
- 微信登录后提交注册申请，管理员审核通过后才能预约
- 课题管理：管理员维护正式课题目录，用户搜索课题或提交新课题申请
- 支持按小时预约，同一预约单支持不连续多时段选择，整单冲突检测和审核
- 普通时段自动确认，夜间、周末和非工作时间命中审核规则
- 工作时间变更后自动触发已有预约的规则复审
- 支持取消预约、取消审核、候补转正和候补通知
- 候补只推进同一时段集合的队首记录，确认窗口最多 2 小时，超时自动失效
- 维护取消、规则拒绝、账号暂停等重要变更通过强提醒通知用户
- 支持管理员维护时间、用户管理、课题审核和统计查看
- 隐私合规：用户服务协议和隐私政策同意、结构化隐私请求（查询、更正、删除、撤回同意、账号注销）
- 数据生命周期：预约记录保留 365 天、过期数据匿名化为月度统计后定时清理，注销时同步清理隐私请求关联
- 个人面板可查看我的预约记录、统计、隐私请求和账号状态

## 技术栈

- 微信小程序
- 微信云开发 / CloudBase
- 云函数
- 原生 `WXML` / `WXSS` / `JS`

## 快速开始

1. 使用微信开发者工具打开仓库根目录。
2. 在 `project.config.json` 中确认 `appid` 和云开发环境配置。
3. 执行根目录依赖安装。

```bash
npm install
```

4. 在微信开发者工具中构建 npm。
5. 为云函数安装依赖并部署。

可选代码检查：

```bash
npm run lint
```

当前仓库已补充根级 ESLint 配置，但仍存在较多历史风格问题；该命令适合作为扫描和回归参考，不代表当前仓库应当零告警。

### 云函数部署

每个云函数目录下都有自己的 `package.json`，可以在微信开发者工具里逐个上传并部署，或使用 CloudBase CLI 批量部署。

```bash
tcb fn deploy <function-name> --dir cloudfunctions/<function-name> -e <env-id>

# 按 cloudbaserc.json 批量覆盖部署全部 57 个业务函数
tcb fn deploy --all --force -e <env-id>
```

首次部署、生产更新、管理员初始化、数据库集合和索引配置，请按
[`docs/deployment-and-operations.md`](docs/deployment-and-operations.md) 执行。

### 本地预览

1. 打开微信开发者工具。
2. 导入本仓库。
3. 选择对应云环境。
4. 运行 `miniprogram/app.json` 中定义的页面。

## 项目特性

- 周历为主界面，强调按天分列、按小时分行的预约视图
- 登录与注册分离，注册需管理员审核
- 课题与注册分离：管理员维护课题目录，用户搜索或申请新课题
- 预约、取消和候补都按整单处理，同一预约单支持多时段不连续选择
- 维护和特殊时段会触发不同的审核和占用规则；受限时段治理已收敛为维护模型
- 预约创建与候补转正会在服务端强制校验维护模式、法务版本、账号状态、确认截止时间，并通过互斥锁串行化关键写入
- 隐私优先：最小必要信息采集，结构化隐私请求，三级信息视图（公开/本人/管理员）
- 管理员治理覆盖课题审核、隐私请求处理、维护模式、规则复审、用户暂停/恢复

## 注意事项

- 该项目使用微信云开发能力，部分功能需要先配置云环境和数据库集合。
- 预约、审核、候补和统计逻辑均依赖云函数，不建议直接修改前端绕过接口。
- 管理员角色必须在 `users` 集合中由受信任的运维人员手动授予，前端不能自助获得管理员权限。
- `tcb fn invoke` 没有小程序用户的微信 `OPENID` 上下文，不能代替管理员在小程序内执行受保护操作。
- 提交到 GitHub 前，建议先检查是否已绑定真实的云环境配置。
