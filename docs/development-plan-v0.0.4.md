## 1. 文档定位

本文档定义 `v0.0.4` 的开发目标、功能范围、页面改造点、服务端影响、验收口径和实施优先级，用于承接 `v0.0.3` 结束后的下一轮迭代。

如与既有文档冲突，按以下顺序执行：

1. 本文档 `development-plan-v0.0.4.md`
2. `execution-baseline-v2.md`

本文档只对 `v0.0.4` 生效，不回改 `v0.0.3` 的收敛口径。

## 2. 版本目标

`v0.0.4` 在不扩大核心预约业务边界的前提下，重点解决以下三类问题：

1. 当前竖版周历同屏信息量有限，管理员和高频用户在查看整周排布时效率不够高。
2. 首页缺少统一的管理信息触达能力，重要运营提示无法在用户进入主页时稳定展示。
3. 管理功能入口仍然偏散，尤其是课题管理未纳入统一管理入口，后台结构还可以继续收拢。

本版本目标如下：

1. 提供稳定可用的横版页面能力，优先服务周历浏览与管理操作。
2. 增加首页信息弹窗，用于展示管理员发布的运营/通知类信息。
3. 将管理相关页面继续收口，把课题管理并入统一入口。
4. 保持当前隐私、权限、法务与内容安全边界不回退。

---

## 3. 版本范围

### 3.1 本次纳入

1. 新增横版页面能力，覆盖周历主浏览场景，并扩展到“我的”等高频页面。
2. “我的”等页面在本版本中优先覆盖：我的首页、我的预约、我的课题。
3. 首页新增管理信息弹窗展示能力。
4. 后台新增统一管理入口页，并将课题管理纳入该入口。
5. 为上述功能补齐必要的文案、状态、权限与数据刷新逻辑。

### 3.2 本次不纳入

1. 不新增新的预约规则、审核规则或统计口径。
2. 不引入图片公告、富文本公告或外部消息推送。
3. 不扩展为多级后台菜单系统或复杂 CMS。
4. 不改动现有隐私文档的核心业务范围，除非联动文案确有必要。

## 4. 默认产品口径

本节先给出 `v0.0.4` 的默认方案，后续若你确认要调整，可直接修改本节作为新口径。

### 4.1 横版页面能力

推荐方案：**以周历横版页为起点，并逐步扩展到“我的”等页面的横版适配能力**，而不是只做单页孤立改造。

执行口径：

1. 当前 [`pages/calendar/index`](../miniprogram/pages/calendar/index.js) 继续保留为竖版主入口。
2. 新增一个横版周历页，承接“同屏看更多时段 / 更多日期”的需求。
3. 对“我的首页”“我的预约”“我的课题”补充横版布局适配，优先处理信息密度和操作可达性，不另起新的业务分支。
4. 横版页和横版适配页优先复用现有数据源、状态颜色、点击分流和权限逻辑。
5. 本版本只优化布局与浏览效率，不在 `v0.0.4` 中叠加新的预约规则。
6. 所有横版页面保持白底、纯文本、无图片、无动画扩展，继续遵守当前视觉规范。

推荐原因：

1. 可以先以周历作为第一落点，再把横版规范复用到“我的”等页面。
2. 风险比“一次性重做所有页面布局”更可控。
3. 便于后续沉淀一套横版适配规范，而不是只做单页特例。

### 4.2 首页管理信息弹窗

推荐方案：**首页展示单条当前生效的管理信息弹窗**，由管理员发布和维护。

执行口径：

1. 弹窗展示位置为首页周历页，即 [`pages/calendar/index`](../miniprogram/pages/calendar/index.wxml)。
2. 每次进入首页时先读取当前是否存在生效中的管理信息。
3. 若存在，则以统一白底弹窗展示标题、正文和发布时间。
4. 用户可明确关闭，关闭后本地记住当前消息版本，避免同一条消息在同一设备上反复弹出。
5. 新消息发布后，通过版本号或更新时间使其重新弹出。
6. 公告内容仅支持纯文本标题和正文，不支持图片、链接跳转、附件和富文本。
7. 管理信息仅作为站内提示，不接入订阅消息、短信、邮件或公众号模板推送。
8. 弹窗默认仅对已登录用户展示，游客进入首页时不弹出。

### 4.3 管理入口收拢

推荐方案：**新增统一管理入口页“页面/课题管理”**，把“维护 / 课题管理 / 系统设置 / 首页管理信息”收纳到同一个入口体系下。

执行口径：

1. 管理首页继续以“待办直达”为第一优先区。
2. 当前“其他功能”区收敛为单一入口“页面/课题管理”。
3. 该入口进入后，再展示：
   - 维护管理
   - 课题管理
   - 系统设置
   - 首页管理信息
4. 课题管理页本身继续沿用现有能力，不在本版本中扩展课题模型。
5. 后台首页不再直接平铺多个低频入口，减少首页认知负担。

## 5. 功能需求

### 5.1 横版周历页

#### 5.1.1 目标

让用户在横向空间更充足的场景下，更高效地查看整周时段分布和预约状态。

#### 5.1.2 页面要求

1. 保留现有周切换、工作时间/全天切换和图例说明。
2. 同步现有公开展示分级：
   - 普通用户只见可公开信息。
   - 管理员可见“课题简称 + 预约人姓名”。
3. 保留现有点击分流：
   - 空闲格进入预约或维护流程。
   - 已预约格进入详情。
   - 待审核格进入待审处理。
   - 维护格进入维护信息。
4. 不改变现有云函数协议，优先复用 `getPublicCalendar`。

#### 5.1.3 交互要求

1. 竖版首页需要提供明确入口进入横版页。
2. “我的首页”“我的预约”“我的课题”需要给出稳定的横版布局或明确的横屏展示策略。
3. 横版页需要提供明确返回方式，不要求用户依赖系统手势理解结构。
4. 若横版页仍支持多选预约，则规则与竖版页保持一致，不允许另起一套选择逻辑。

### 5.2 首页管理信息弹窗

#### 5.2.1 目标

让管理员可以向进入首页的用户展示一条当前生效的重要信息，用于运营通知、规则提醒或阶段性公告。

#### 5.2.2 数据要求

建议最小字段如下：

1. `title`
2. `content`
3. `enabled`
4. `version`
5. `publishedAt`
6. `updatedAt`

可选字段：

1. `targetScope`：全部用户 / 仅管理员 / 仅已登录用户

#### 5.2.3 规则

1. 只有管理员可创建、编辑、启停管理信息。
2. 内容提交前必须经过服务端内容安全校验；校验失败时禁止发布。
3. 当前无生效信息时，首页不弹窗。
4. 游客不展示该弹窗；仅已登录用户进入首页时参与弹窗判断。
5. 同一版本消息在同一设备关闭后不重复打扰。
6. 新版本消息可再次触达。
7. 弹窗必须有明确关闭操作，不通过遮罩强制关闭。

#### 5.2.4 页面归属

推荐把管理信息的编辑入口放入统一管理入口页下，而不是继续塞进首页待办区。

### 5.3 管理入口页

#### 5.3.1 目标

进一步压缩管理首页的低频入口数量，让管理员先看到待办，再进入统一的配置/目录管理区域。

#### 5.3.2 页面结构

统一管理入口页建议至少包含以下分组：

1. 运行管理：维护管理、系统设置
2. 目录管理：课题管理
3. 信息管理：首页管理信息

#### 5.3.3 关系调整

1. [`pages/admin/index`](../miniprogram/pages/admin/index/index.js) 只保留待办直达和统一入口卡片。
2. [`pages/admin/projects`](../miniprogram/pages/admin/projects/index.js) 继续作为具体子页面存在，但不再在管理首页直接裸露。
3. 若新增首页管理信息编辑页，也从统一入口页进入。

## 6. 前后端影响

### 6.1 前端

预计涉及以下区域：

1. [`miniprogram/pages/calendar/`](../miniprogram/pages/calendar/index.js)：新增横版入口与首页弹窗展示逻辑。
2. `miniprogram/pages/calendar-landscape/` 或等效新页面：承接横版周历布局。
3. [`miniprogram/pages/profile/index/`](../miniprogram/pages/profile/index/index.js)、[`miniprogram/pages/profile/bookings/`](../miniprogram/pages/profile/bookings/index.js)、[`miniprogram/pages/profile/project/`](../miniprogram/pages/profile/project/index.js)：补充横版适配策略。
4. [`miniprogram/pages/admin/index/`](../miniprogram/pages/admin/index/index.js)：收拢为单一管理入口。
5. `miniprogram/pages/admin/manage-hub/` 或等效新页面：统一承接低频管理功能。
6. `miniprogram/pages/admin/home-notice/` 或等效新页面：维护首页管理信息。
7. [`miniprogram/app.json`](../miniprogram/app.json)：注册新增页面。

### 6.2 云函数

推荐优先采用“新增轻量管理信息接口”方案，而不是把公告字段直接混入所有现有接口。

建议新增或改造的能力：

1. `getHomeNotice`：获取当前生效的首页管理信息。
2. `updateHomeNotice`：管理员创建、编辑、启停首页管理信息。
3. 如需减少函数数量，也可评估并入现有 `getSettings` / `updateSettings`，但前提是保持职责清晰。

服务端要求：

1. 管理员权限二次校验。
2. 字段白名单返回，不回传无关配置。
3. 文本内容安全校验失败时闭锁。
4. 记录版本号或更新时间，支撑客户端判重展示。

## 7. 验收口径

满足以下条件后，可视为 `v0.0.4` 完成：

1. 首页可通过明确入口进入横版页。
2. 横版页能正确展示周历、图例、状态和点击分流。
3. “我的首页”“我的预约”“我的课题”已完成横版适配，且不影响原有业务流程。
4. 横版页不引入与竖版不一致的预约或维护规则。
5. 管理员可发布、修改、停用首页管理信息。
6. 生效中的管理信息只对已登录用户在首页弹窗展示，关闭后同版本不重复弹出。
7. 发布新版本管理信息后，已关闭旧版本的用户仍能看到新消息。
8. 管理首页不再直接散列多个低频入口，课题管理已纳入“页面/课题管理”统一入口。
9. 非管理员无法进入管理信息编辑能力，也无法绕过服务端修改公告。
10. 所有新增文本输入遵守内容安全与失败闭锁要求。

---

## 8. 风险与注意事项

1. 横版页如果直接复制竖版逻辑，容易产生双页行为不一致，需优先抽取共享状态和事件处理。
2. 管理信息若没有版本控制，会导致客户端无法稳定判断“是否弹过”。
3. 管理入口收拢后，需避免路径层级变深导致常用低频功能反而更难找。
4. 弹窗文案必须控制长度，避免在窄屏和字体放大场景下溢出。

---

## 9. 实施优先级

为避免 `v0.0.4` 在实现期再次发散，本版本默认按以下顺序推进：

1. 第一优先级：周历横版页、首页管理信息弹窗、管理首页统一入口。
2. 第二优先级：我的首页、我的预约、我的课题三页的横版适配。
3. 第三优先级：统一入口中的首页管理信息编辑页与细节文案打磨。

本版本固定采用以下口径：

1. 横版覆盖周历主页面，并扩展到我的首页、我的预约、我的课题。
2. 首页管理信息仅面向已登录用户。
3. 统一入口命名为“页面/课题管理”。
4. “页面/课题管理”入口内按“运行管理 / 目录管理 / 信息管理”分组展示。
