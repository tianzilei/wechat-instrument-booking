## 2. 产品边界

### 2.1 服务对象

- 单台实验室仪器。
- 仅面向年满 18 周岁且具备实验室使用资格的用户。
- 用户资格由管理员根据线下名单或实际认识核验。
- 小程序不收集身份证明、学生证、证件图片或额外联系方式。

### 2.2 角色

| 角色 | 权限 |
| --- | --- |
| 游客 | 查看周历公开占用状态和公开详情 |
| 普通用户 | 注册通过后预约、取消、候补、查看本人记录和统计 |
| 管理员 | 用户/课题/预约/取消审核、维护、用户管理、整体统计 |

管理员角色只允许在云开发控制台人工设置。小程序内不得提供管理员申请、邀请码或角色授予入口。

### 2.3 核心业务原则

- 注册审核通过后立即获得预约资格，不增加第二层资格审批。
- 用户只能归属一个有效课题。
- 预约最小单位为 1 小时，所有时间必须为整点。
- 单次预约总时长和格子数量不设上限。
- 一张预约单可以包含同一自然周内多个不连续时段。
- 冲突、审核、候补和取消均按整张预约单处理。
- 维护时间绝对不可预约，并可覆盖未来预约。
- 普通预约自动确认；特殊预约整单进入管理员审核。

## 3. 已废弃设计

以下内容不得继续实现或保留：

- 注册收集手机号、邮箱、学号、学院、导师或负责人。
- 获取、存储或展示微信昵称和头像。
- 在客户端展示 `openid`。
- 通过上传证明图片核验注册资格。
- 长按后拖动选择时间。
- 强制不连续选择最终变为连续时段。
- 每个小时创建一条独立预约。
- 在公开周历展示姓名、备注、审核意见或真实预约 ID。
- 管理员周历格始终展示姓名。
- 用户、课题预约时长排行。
- 外部短信、电话或订阅消息通知。
- 图标式底部导航、图标宫格、插画、渐变或大量动效。

## 4. 课题与注册

### 4.1 课题目录

课题是独立业务对象，由管理员维护正式目录。

正式课题包含：

- 课题名称 `name`
- 唯一课题缩写 `abbr`
- 状态 `active/inactive`
- 创建、修改、停用信息

课题只能停用，不能删除。停用课题可以重新启用，但不会自动恢复成员、预约或候补。

课题名称或缩写变更后：

- 当前界面和历史预约统一显示新名称/缩写。
- 后台更新全部关联快照。
- 审计日志保留修改前后值、管理员和时间。
- 更新必须采用可重试批处理，禁止出现部分记录新旧混杂。

### 4.2 查找已有课题

- 用户输入至少 2 个字符后搜索。
- 最多返回 5 条启用中的匹配课题。
- 只显示课题名称和缩写。
- 不允许浏览完整课题目录。
- 搜索仅针对本系统课题，不属于微信小程序搜索功能。

### 4.3 新增课题申请

用户找不到课题时，可在注册流程中填写：

- 课题名称
- 建议课题缩写

提交前执行名称和缩写相似匹配，最多提示 5 个疑似重复课题。提示不阻止用户继续提交。

新增课题与个人注册采用两阶段流程：

1. 用户提交课题申请。
2. 管理员审核课题申请。
3. 课题通过后进入正式课题目录。
4. 用户查看管理员最终确认的名称和缩写。
5. 用户主动确认课题归属。
6. 系统创建个人注册申请。
7. 管理员审核个人注册。

课题通过后的用户确认不设期限。

管理员发现重复课题时必须拒绝申请，不允许直接合并到已有课题。拒绝原因选填；建议在原因中指出应选择的已有课题。

### 4.4 个人注册

用户注册时实际提交：

- 姓名
- 已有课题 ID，或已通过并由本人确认的新课题 ID
- 服务协议和隐私政策同意记录

注册页必须显示简短数据用途说明，并提供一个默认未勾选的复选框：

```text
我已阅读并同意《用户服务协议》和《隐私政策》
```

后台分别保存两份文档的版本和同意时间。

《用户服务协议》应明确要求用户填写真实、准确的姓名，并声明用户须年满 18 周岁且具备相应实验室使用资格。注册页不增加年龄、身份证明或额外真实性复选框。

同一用户同时只能存在一条待审核注册申请。待审核申请不能撤回或修改；被拒绝后创建新的申请记录，旧记录保留一年。

注册拒绝原因选填。未填写时显示“注册申请未通过，未提供具体原因”。

### 4.5 用户状态

建议使用“账号状态 + 注册流程状态”两个维度，避免单个枚举失控。

账号状态 `accountStatus`：

| 值 | 说明 |
| --- | --- |
| `active` | 正常账号 |
| `suspended` | 管理员无限期暂停 |
| `project_reassignment_required` | 原课题停用，需重新选择课题 |
| `deleting` | 注销处理中 |
| `deleted` | 已注销，仅用于任务终态，不保留个人资料 |

注册流程状态 `registrationStatus`：

| 值 | 说明 |
| --- | --- |
| `unsubmitted` | 未提交 |
| `project_pending` | 新课题审核中 |
| `project_confirm_required` | 新课题已通过，等待本人确认 |
| `registration_pending` | 个人注册审核中 |
| `approved` | 注册通过 |
| `rejected` | 最近一次注册被拒绝 |

可预约条件必须同时满足：

```text
role in [user, admin]
accountStatus == active
registrationStatus == approved
project.status == active
已同意当前协议版本
系统未处于维护或规则迁移暂停状态
```

### 4.6 资料变更

- 姓名不能直接编辑。
- 姓名更正通过“隐私请求-更正”提交，由管理员线下核验后修改。
- 姓名更正批准后立即生效。
- 更正日志保存一年。
- 变更所属课题必须重新审核。
- 课题变更审核期间保留原课题关系，但暂停创建新预约。
- 变更被拒绝后继续使用原课题。
- 账号暂停期间禁止姓名和课题变更。

### 4.7 账号暂停与课题停用

管理员暂停用户时：

- 必须填写暂停原因并确认影响范围。
- 无限期暂停，只能管理员手动恢复。
- 自动取消该用户全部未来预约和候补。
- 已开始和历史记录不受影响。
- 用户下次进入时收到重要变更强提醒。
- 恢复账号不会恢复已取消预约。

管理员停用课题时：

- 必须填写原因并确认受影响成员、预约和候补数量。
- 自动取消该课题全部未来预约和候补。
- 成员账号改为 `project_reassignment_required`。
- 用户重新选择或申请课题并审核通过前不能预约。
- 重新启用课题不会恢复成员关系和预约。

## 5. 时间与周历

### 5.1 基础时间规则

| 规则 | 值 |
| --- | --- |
| 时区 | `Asia/Shanghai` |
| 最小预约单位 | 1 小时 |
| 时间精度 | 整点 |
| 默认工作时间 | 每天 `09:00-18:00` |
| 周末 | 全部预约需审核 |
| 提前范围 | 当前日期至第 7 个自然日，含首尾日期 |
| 周历浏览范围 | 当前周前后各 4 周 |
| 取消审核边界 | 最早未开始时段前 12 小时 |
| 候补确认窗口 | 最多 2 小时 |

工作时间每天统一配置，不允许跨午夜，只允许整点。周末即使位于 `09:00-18:00` 也属于特殊预约。

提前 7 天按中国标准时间的自然日计算。例如 6 月 10 日可预约到 6 月 17 日 `23:00-24:00`。所有选中格必须处于允许范围；任一越界则整单失败。

### 5.2 过去和当前小时

当前小时整体不可预约。例如当前为 `10:20`：

- `10:00-11:00` 灰显并不可编辑。
- 最早可预约 `11:00-12:00`。

过去时段保留在周历中，统一浅灰显示，布局不随时间移动。过去预约对公众只显示“已结束”，不显示课题缩写。

前端时间只用于展示；提交、候补和审核必须使用云函数服务器时间再次校验。

### 5.3 周历浏览

- 默认显示工作时间 `09:00-18:00`。
- 全天模式显示完整 `00:00-24:00`，切换后定位到 `09:00`。
- 当前周横向定位到今天，其他周从周一开始。
- 手机约同时显示 3 天，横向滚动查看其他日期。
- 宽屏在空间足够时显示完整 7 天。
- 日期表头和左侧时间列固定。
- 周末只在日期表头显示“周末”标签，不改变整列颜色。
- 超出预约范围的日期仍可浏览，但格子灰显且不可选择。

### 5.4 公开展示矩阵

| 状态 | 游客/普通用户 | 本人 | 管理员周历格 |
| --- | --- | --- | --- |
| 已确认未来预约 | 课题缩写 | 课题缩写 +“我的”标记 | 课题缩写 |
| 待审核 | “审核中” | “审核中”+“我的” | “审核中” |
| 取消审核中 | 课题缩写 + 状态 | 完整本人状态 | 课题缩写 + 状态 |
| 候补 | 不显示 | 候补页查看 | 不显示 |
| 过去预约 | “已结束” | 本人历史详情 | 管理记录查看 |
| 维护 | “维护中，不可预约” | 相同 | 相同 |
| 受限 | “该时段预约需要管理员审核” | 相同 | 相同 |

管理员周历格默认不显示姓名。管理员点击预约后，独立调用管理员详情接口查看姓名。

公开接口不得返回：姓名、课题全称、备注、审核意见、`openid`、真实预约 ID。

点击行为：

- 游客点击可预约格：显示“暂不注册/申请注册”引导弹窗。
- 游客点击已占用格：只看公开占用详情，不显示候补或注册引导。
- 未获得预约资格的用户点击可预约格：根据课题审核、注册审核、暂停或重新归属状态显示对应下一步。
- 普通用户点击他人已占用格：先看公开详情，再决定是否为当前 1 小时加入候补。
- 用户点击本人预约格：打开整张预约单详情，不提供单小时取消。
- 点击维护或受限格：只显示简短状态说明，不展示内部原因或管理员信息。

## 6. 时间选择与预约单

### 6.1 单小时预约

- 浏览状态点击可预约格，打开 1 小时预约确认弹窗。
- 不允许点击后直接提交。
- 弹窗展示时段、审核提示和选填备注。

### 6.2 多选模式

- 长按可预约格进入多选模式并选中该格。
- 后续通过点击格子切换选中/取消。
- 不使用拖动选择。
- 允许多个不连续时段。
- 不限制格子数量或总时长。
- 所有选择必须位于同一自然周。
- 切换周前提示并清空选择。
- 多选期间禁止下拉刷新和切换“工作时间/全天”。
- 顶部固定操作栏显示：退出选择、已选小时、清空、确认。
- “清空”直接执行但保持多选模式。
- 未选中格子时确认按钮禁用。
- 提交成功后清空选择并退出多选。

### 6.3 预约单时间模型

一张预约单包含多个标准化时段：

```js
segments: [
  {
    startAt: Date,
    endAt: Date,
    state: 'active' // active / cancelled
  }
]
```

标准化要求：

- 按 `startAt` 升序排列。
- 去除重复小时。
- 同一天相邻小时合并为连续时段。
- 时段之间不得重叠。
- 所有时段必须处于同一自然周。
- `durationHours` 为所有 `active` 时段总小时数。
- `firstStartAt`、`lastEndAt` 为查询冗余字段。
- `scheduleKey` 为规范化时段集合哈希，用于幂等和候补去重。

预约单级 `status` 表示审批和业务流程；时段级 `state` 表示该时段是否仍有效。已结束时段是否完成由服务器时间推导，不单独批量改写状态。

这样可以支持：一张预约单部分时段已结束、未来时段整单取消、按小时统计，以及历史部分继续保留。

预约单 `status` 只允许以下值：

| 状态 | 是否占用未来有效时段 | 说明 |
| --- | --- | --- |
| `pending_review` | 是 | 特殊预约等待首次审核 |
| `confirmed` | 是 | 已确认，可包含已经结束的历史时段 |
| `rule_review_pending` | 是 | 新规则命中后等待复审 |
| `cancel_pending` | 是 | 12 小时内取消等待审核，`previousStatus` 保存进入前状态 |
| `rejected` | 否 | 首次预约审核被拒绝 |
| `review_timeout` | 否 | 首次审核超过最早开始时间 |
| `cancelled` | 否 | 用户直接取消或取消审核通过；已结束时段仍保留历史 |
| `maintenance_cancelled` | 否 | 未来时段因维护取消 |
| `rule_rejected` | 否 | 规则复审拒绝并取消未来时段 |

“已完成”不是预约单写入状态，而是 `status == confirmed` 且目标时段 `endAt <= now` 的派生展示。取消审核被拒绝或超时后恢复 `previousStatus`，并把结果写入业务时间线。

### 6.4 创建预约

提交内容：

```js
{
  requestId,
  segments: [{ startAt, endAt }],
  remark
}
```

- `requestId` 必须实现服务端幂等。
- 备注选填，最多 100 字。
- 任一时段命中维护、已有占用、越界或过去时间，整单失败。
- 冲突失败后前端保留全部选择并标记冲突格。
- 任一时段命中非工作时间、周末或受限规则，整单 `pending_review`。
- 否则整单 `confirmed`。
- 待审核预约的所有时段立即占用。

确认弹窗按日期分组并合并相邻小时，只提示“整单需要审核”，不展开规则细节。

提交期间：

- 禁止关闭弹窗和切换页面。
- 前端按钮防连点，服务端用 `requestId` 幂等。
- 普通预约成功提示“预约成功”；特殊预约提示“已提交审核”。
- 成功后关闭弹窗、清空选择、退出多选并刷新周历。
- 冲突失败保留全部选择，冲突格使用危险状态标记，不自动移除。

### 6.5 冲突状态

以下预约流程状态占用时间：

- `confirmed`
- `pending_review`
- `rule_review_pending`
- `cancel_pending`
- 候补临时锁定

冲突检测必须在数据库事务或等效原子流程中完成，不能依赖 30 秒周历缓存。

### 6.6 预约审核

- 管理员逐单审核，不提供批量审核。
- 按最早预约时段升序排列，相同时间按提交时间排序。
- 管理员只能整单通过或整单拒绝。
- 拒绝原因选填。
- 未填写原因时本人详情显示“管理员未填写拒绝原因”。
- 到最早时段开始仍未处理，整单变为 `review_timeout` 并释放全部未来时段。

## 7. 取消预约

### 7.1 整单取消

- 不允许取消预约单中的单个时段。
- 用户发起取消时，操作对象是所有尚未开始且 `active` 的时段。
- 已开始或已结束时段保留为历史记录。
- 取消说明选填，最多 100 字。

### 7.2 是否需要审核

以预约单中最早的未开始有效时段判断：

- 距离开始不少于 12 小时：直接取消所有未来有效时段。
- 距离开始不足 12 小时：整单进入 `cancel_pending`。
- 审核期间全部未来时段继续占用。

取消确认弹窗必须列出全部未来时段，并明确说明“立即取消”或“进入审核”。

### 7.3 取消审核

- 按最早未开始时段升序排列。
- 批准后取消全部未来有效时段。
- 拒绝后恢复取消前预约状态。
- 到最早未开始时段开始仍未处理，取消申请自动驳回并记录 `cancel_review_timeout`。

预约详情必须显示完整业务时间线，包括提交、审核、取消申请、取消结果、维护取消、规则复审和审核超时。时间线不显示管理员姓名或内部审计数据。

## 8. 候补

### 8.1 加入方式

候补有两种入口：

1. 点击单个已占用格，只为当前 1 小时候补。
2. 多时段预约冲突弹窗中，将原预约单全部时段整单加入候补。

部分冲突时也必须整单候补，不能只候补冲突部分。

同一用户不能重复加入完全相同的一组时段。候补记录不显示排队名次或前方人数。

### 8.2 转正

- 只有全部候补时段同时可用时才处理队首记录。
- 系统临时锁定全部时段。
- 默认确认期限为 2 小时。
- 若距离最早时段不足 2 小时，截止时间为最早时段开始前。
- 用户可随时取消候补；锁定期间取消等同主动放弃。
- 放弃或超时后立即顺延下一位。
- 如果确认时命中新特殊规则，转为 `pending_review`，继续占用全部时段。
- 若最早时段已开始，整单候补过期。

### 8.3 候补通知

通知中心只承担候补通知：

- 已获得临时锁定，等待确认
- 确认即将截止
- 已转正
- 已放弃或已过期

不使用微信订阅消息，不收集手机号或邮箱。用户未打开小程序时不会收到外部提醒。

## 9. 维护和工作时间规则

### 9.1 优先级

```text
系统维护/规则迁移暂停
→ 仪器维护（绝对禁止）
→ 已占用（可候补）
→ 非工作时间/周末（需审核）
→ 普通预约（自动确认）
```

### 9.2 维护时间

- 管理员通过周历逐格多选创建，可包含多个不连续时段。
- 维护不自动生成前后缓冲区。
- 需要缓冲时，管理员直接新增覆盖缓冲区的维护时段。
- 创建前显示受影响预约单和时段数量。
- 管理员填写维护说明并确认。
- 任一未来有效时段命中维护时，整张预约单按“维护取消”处理。
- 已开始或已结束时段不追溯取消。
- 相关候补锁定释放，并重新计算候补队列。

工作时间变更后：

- 命中新规则的未来预约整单进入 `rule_review_pending`。
- 复审期间继续占用全部未来有效时段。
- 批准后恢复 `confirmed`，不强提醒。
- 拒绝后取消整单未来时段，并加入重要变更强提醒。
- 已开始和已完成时段不追溯。

### 9.3 工作时间配置迁移

工作时间保存在数据库，由管理员直接修改。配置必须包含递增 `version`。

云函数首次发现新版本时：

1. 原子创建唯一规则迁移任务。
2. 暂停新预约、加入候补、候补确认、预约审核和规则复审。
3. 周历保持可查看，并显示“预约规则更新中”。
4. 扫描全部未来预约。
5. 将命中新规则的预约转入规则复审。
6. 记录已处理版本并恢复服务。

注册审核和取消审核在规则迁移期间仍可处理。

扫描失败时保持暂停，不得忽略失败或自动开放。管理员修复配置或版本后重新扫描。

## 10. 提醒与消息

### 10.1 重要变更

重要变更不进入候补通知中心，使用单独的未读事件集合和强提醒弹窗：

- 维护导致预约取消
- 规则复审拒绝
- 账号暂停
- 课题停用导致预约取消或需重新归属

多个事件合并为“重要变更”弹窗，每条只显示类型、时间和一句摘要。用户必须点击“我知道了”后才能继续业务操作；退出登录和注销不受阻断。

### 10.2 普通审核结果

注册、预约和取消审核结果不创建站内通知。用户在对应申请或预约详情中查看。

## 11. 隐私和账号

### 11.1 最小必要信息

用户主动填写的个人信息只有姓名。用户还会选择课题关系；申请新课题时填写课题名称和建议缩写。

系统处理但不向其他用户展示：

- `openid`：账号技术标识
- 协议版本和同意时间
- 注册、预约、审核和隐私请求状态
- 必要审计字段

不得收集：手机号、邮箱、学号、学院、导师、微信昵称、微信头像、位置、通讯录、相册、摄像头、麦克风等非必要信息。

静默身份识别只查询已有账号。游客仅浏览周历时，`login` 不得自动创建持久化用户档案。只有用户主动提交注册/课题申请并同意当前协议后，才持久保存与账号申请相关的数据。

### 11.2 协议更新

协议或隐私政策版本更新后，登录用户必须重新主动同意。未同意前：

- 可以阅读新旧版本和变更说明。
- 可以退出登录或注销账号。
- 可以处理已有预约取消，避免继续占用时段。
- 禁止预约、候补、资料变更和其他业务操作。

撤回隐私同意等同进入账号注销流程，必须二次确认。

### 11.3 隐私请求

“我的 → 账号与隐私”提供结构化请求：

- 查询
- 更正
- 删除
- 撤回同意
- 注销
- 投诉

补充说明选填，不要求额外联系方式。管理员端增加“隐私请求”待办。

状态：

```text
pending → processing → completed / rejected
```

不承诺固定处理天数，政策表述为“核验后尽快处理”。用户可以查看完整状态和管理员处理说明。

完成后保留 90 天，再删除或匿名化用户关联、说明和回复，只保留匿名数量统计。

查询请求直接在页面展示姓名、当前课题、注册状态、协议记录和保存规则，不生成下载文件。

核心资料无法在保留预约服务时单独删除，应说明原因并提供注销入口。

### 11.4 注销

- 用户二次确认后立即进入注销，无冷静期，无需管理员批准。
- 注销开始后不可撤销。
- 使用后台任务和状态机，不在单次云函数中同步完成全部清理。
- 进入 `deleting` 后禁止全部业务操作，返回身份识别/游客页面。
- 登录页或入口状态显示“账号注销处理中”。
- 完成前不能重新注册。

注销任务步骤：

1. 幂等锁定账号。
2. 取消全部未来预约和候补，不受 12 小时规则限制。
3. 重新计算候补队列。
4. 删除通知和协议记录。
5. 删除用户资料和课题成员关系。
6. 历史预约解除用户关联并匿名化。
7. 隐私请求按规则完成清理。
8. 清除客户端会话。

任务失败自动重试；超过次数后生成高优先级隐私待办。管理员只能修复或重跑，不能恢复账号。

注销完成后，同一微信可立即作为全新用户注册，不能恢复旧资料和历史关系。

注销匿名化时必须移除历史预约的 `userId`、姓名、`openid` 和可回溯的课题成员关系。只保留仪器整体统计所需的时间、时长、状态和匿名业务原因；不得通过课题 ID 反向定位已注销用户。

### 11.5 输入内容安全

以下自由输入必须在云函数写入前执行长度、格式、空白处理和微信文本内容安全检测：

- 姓名
- 课题名称和建议缩写
- 预约备注
- 取消说明
- 各类审核拒绝原因
- 维护说明
- 暂停和停用原因
- 隐私请求补充说明
- 隐私请求处理说明

内容检测不通过时不写入数据库。日志只记录错误码和追踪 ID，不记录原始正文。

课题缩写建议限制为中文、英文字母、数字、连字符和下划线，长度 1-20 个字符。姓名和课题名称需设置合理上限，前后端规则保持一致。

## 12. 数据保存

| 数据 | 保存规则 |
| --- | --- |
| 预约、审核、取消、维护、管理员业务操作明细 | 365 天 |
| 满一年业务数据 | 匿名月度汇总后删除明细 |
| 隐私请求完成记录 | 90 天后删除或匿名化 |
| 技术错误日志 | 30 天 |
| 迁移加密备份 | 验证完成后 7 天内删除 |

匿名月度汇总只保留：总完成小时、工作时间使用率、特殊时段小时、取消次数、维护小时。不得保留用户、课题或预约单关联。

## 13. 数据库目标模型

### 13.1 `users`

```js
{
  _id,
  openid,
  role,                       // user / admin
  accountStatus,              // active / suspended / ...
  registrationStatus,
  name,
  projectId,
  suspendedReason,
  suspendedAt,
  agreementVersion,
  agreementAcceptedAt,
  privacyVersion,
  privacyAcceptedAt,
  createdAt,
  updatedAt,
  lastLoginAt
}
```

`openid` 唯一。不得保留手机号、邮箱、学号、学院、导师、昵称和头像字段。

### 13.2 `projects`

```js
{
  _id,
  name,
  abbr,
  normalizedName,
  normalizedAbbr,
  displayVersion,
  status,                     // active / inactive
  inactiveReason,
  createdBy,
  updatedBy,
  createdAt,
  updatedAt
}
```

`normalizedAbbr` 唯一。名称和缩写变更通过任务更新关联快照。

### 13.3 `project_applications`

```js
{
  _id,
  userId,
  proposedName,
  proposedAbbr,
  status,                     // pending / approved / rejected
  approvedProjectId,
  finalName,
  finalAbbr,
  reviewReason,
  reviewedBy,
  reviewedAt,
  userConfirmedAt,
  createdAt,
  updatedAt
}
```

### 13.4 `registration_applications`

```js
{
  _id,
  userId,
  nameSnapshot,
  projectId,
  status,                     // pending / approved / rejected / terminated
  reviewReason,
  agreementVersion,
  privacyVersion,
  reviewedBy,
  reviewedAt,
  createdAt,
  updatedAt
}
```

同一用户只能存在一条 `pending`。

### 13.5 `bookings`

```js
{
  _id,
  userId,                     // 注销后移除
  projectId,
  projectAbbrDisplayCache,
  projectDisplayVersion,
  requestId,
  scheduleKey,
  segments: [
    { startAt, endAt, state, cancelledAt, cancelReasonCode }
  ],
  firstStartAt,
  lastEndAt,
  durationHours,
  remark,
  status,                     // pending_review / confirmed / ...
  previousStatus,
  bookingType,                // normal / special
  specialReasons,
  reviewReason,
  cancellationNote,
  terminationReasonCode,
  reviewedBy,
  reviewedAt,
  createdAt,
  updatedAt
}
```

`projectAbbrDisplayCache` 只是可更新的查询显示缓存，不是不可变审计快照。课题缩写变更时先递增 `projects.displayVersion`，再同步关联记录。接口发现 `projectDisplayVersion` 落后时必须以 `projects.abbr` 为准，避免批处理期间显示旧缩写。

不得冗余保存 `openid`、姓名或学院。管理员详情按 `userId` 服务端关联当前姓名。

### 13.6 `waitlists`

```js
{
  _id,
  userId,
  projectId,
  scheduleKey,
  segments,
  status,                     // waitlisted / confirming / converted / cancelled / expired
  remark,
  confirmDeadlineAt,
  convertedBookingId,
  createdAt,
  updatedAt
}
```

建立 `userId + scheduleKey + activeStatus` 唯一性保护。

候补 `status` 只允许：`waitlisted`（排队中）、`confirming`（已锁定待确认）、`converted`（已生成预约）、`cancelled`（主动取消/放弃）、`expired`（最早时段已开始或确认超时且无法继续）。候补生成的预约是否需要审核，由新预约自身状态表达。

### 13.7 其他集合

| 集合 | 用途 |
| --- | --- |
| `maintenance_groups` | 一组维护时段及说明 |
| `important_events` | 强提醒事件及已读状态 |
| `notifications` | 仅候补通知 |
| `privacy_requests` | 隐私请求及处理状态 |
| `audit_logs` | 改变状态或数据的管理员操作 |
| `deletion_tasks` | 注销任务状态机 |
| `rule_migration_tasks` | 工作时间配置版本迁移 |
| `monthly_stats` | 匿名月度汇总 |
| `settings` | 工作时间、维护模式、协议版本等 |

管理员普通查看姓名不写审计日志；审核、暂停、恢复、维护和课题变更必须记录。审计日志仅在云开发控制台查看，不在小程序内提供页面或导出。

### 13.8 `settings` 关键字段

```js
{
  _id: 'global',
  timezone: 'Asia/Shanghai',
  openStartHour: 9,
  openEndHour: 18,
  rulesVersion: 1,
  processedRulesVersion: 1,
  serviceMode: 'normal',      // normal / maintenance / rule_migrating
  serviceAgreementVersion: '1.0',
  privacyPolicyVersion: '1.0',
  updatedAt
}
```

工作时间和 `rulesVersion` 必须一起更新。`processedRulesVersion < rulesVersion` 时，预约相关写接口全部进入只读保护。

### 13.9 必要索引

| 集合 | 索引 |
| --- | --- |
| `users` | `openid` 唯一；`accountStatus + registrationStatus` |
| `projects` | `normalizedAbbr` 唯一；`status + normalizedName` |
| `project_applications` | `userId + status`；`status + createdAt` |
| `registration_applications` | `userId + status`；`status + createdAt` |
| `bookings` | `userId + firstStartAt`；`status + firstStartAt`；`lastEndAt` |
| `waitlists` | `userId + scheduleKey + status`；`status + createdAt` |
| `privacy_requests` | `userId + createdAt`；`status + createdAt` |
| `important_events` | `userId + readAt + createdAt` |
| `deletion_tasks` | `userId` 唯一；`status + nextRetryAt` |

多时段冲突不能只依赖 `firstStartAt/lastEndAt` 索引判断，必须对候选预约的 `segments` 逐段比较。

### 13.10 数据库访问权限

客户端不得直接读写业务集合。所有身份裁剪、字段过滤和状态校验统一在云函数完成。

| 数据范围 | 游客 | 普通用户 | 管理员 | 实现方式 |
| --- | --- | --- | --- | --- |
| 公开周历 | 仅公开字段 | 仅公开字段 | 公开视图或管理员详情 | `getPublicCalendar` |
| 本人资料/预约/候补 | 无 | 仅本人 | 按管理职责访问 | 专用云函数 |
| 用户、课题审核和隐私请求 | 无 | 仅本人申请状态 | 可审核 | 管理云函数服务端鉴权 |
| 配置、审计日志、任务集合 | 无 | 无 | 小程序内也不直接读写 | 云函数或云开发控制台 |

云数据库安全规则原则上对小程序客户端关闭全部业务集合读写。即使规则允许某个集合读取，云函数仍必须使用字段白名单，不能把数据库原记录直接返回客户端。

### 13.11 原子操作与批处理边界

以下操作必须使用数据库事务、条件更新、唯一键或等效原子机制：

- 创建预约：幂等校验、冲突复核、预约写入和占用建立。
- 审核预约：校验当前状态后通过，或拒绝并释放全部未来时段。
- 取消预约：状态切换、时段释放和候补推进信号。
- 候补确认：队首校验、全时段锁定、创建预约和候补终态更新。
- 创建维护：维护记录生效前锁定受影响写入，避免新预约插入维护范围。
- 用户暂停、课题停用：先切换禁止写入状态，再由可重试任务取消未来业务记录。

跨多条记录的大批量操作不强行放入单个事务。应使用任务状态机、分页游标、幂等步骤和最终一致性校验；任务未完成期间，对受影响对象保持只读或禁止预约。

## 14. 接口边界

### 14.1 通用要求

- 所有写操作通过云函数。
- 所有管理员接口服务端重新验证角色。
- 所有写请求支持幂等键或状态条件更新。
- 所有返回值采用字段白名单。
- 日志不得记录姓名、`openid`、课题、备注或拒绝原因正文。
- 错误返回稳定业务错误码；用户端统一显示“系统错误，请稍后重试”。
- 用户端系统错误弹窗只提供关闭操作，不增加自动或持续重试按钮。

### 14.2 身份与协议

| 接口 | 用途 |
| --- | --- |
| `login` | 静默识别身份，返回最小用户状态，不向客户端返回 `openid` |
| `getLegalDocuments` | 返回当前协议版本和正文 |
| `acceptLegalDocuments` | 记录用户主动同意 |
| `logout` | 清除本地会话状态，本次会话保持游客 |

进入小程序时周历加载和身份识别并行。识别成功只更新顶部状态文字，不显示“登录成功”提示；识别失败保持游客浏览。退出后本次会话不再自动识别，重新启动小程序时恢复静默识别。

### 14.3 课题与注册

| 接口 | 用途 |
| --- | --- |
| `searchProjects` | 最少 2 字符、最多 5 条结果 |
| `checkProjectSimilarity` | 返回疑似重复课题，不自动拒绝 |
| `submitProjectApplication` | 创建新课题申请 |
| `listProjectApplications` | 管理员查看课题申请 |
| `reviewProjectApplication` | 管理员通过或拒绝 |
| `confirmApprovedProject` | 用户确认最终课题信息 |
| `submitRegistration` | 创建独立注册申请 |
| `listRegistrationReviews` | 管理员查看待审注册 |
| `reviewRegistration` | 通过或拒绝注册 |
| `requestProjectChange` | 提交课题变更审核 |

### 14.4 周历与详情

必须分离三个接口：

| 接口 | 返回范围 |
| --- | --- |
| `getPublicCalendar` | 公开状态、时段、允许公开的课题缩写、临时渲染 ID |
| `getMyBookingDetail` | 本人预约全部时段、备注、审核结果和时间线 |
| `getAdminBookingDetail` | 管理员业务所需详情和当前姓名 |

公共临时 ID 仅在当前周查询中稳定，不可用于详情查询或反推真实预约 ID。

公共周历允许约 30 秒服务端缓存。所有写操作成功后主动失效相关周缓存。提交预约时始终查询实时数据库。

### 14.5 预约、取消和候补

| 接口 | 关键要求 |
| --- | --- |
| `createBooking` | 接受 `segments` 和 `requestId`，事务冲突检测 |
| `reviewBooking` | 整单通过/拒绝 |
| `cancelBooking` | 计算最早未来时段，直接取消或进入审核 |
| `reviewCancel` | 整单处理取消请求 |
| `joinWaitlist` | 接受完整时段集，检查重复 |
| `confirmWaitlist` | 原子锁定、确认、转预约或转审核 |
| `cancelWaitlist` | 随时取消或放弃锁定 |

| 接口 | 用途 |

| `createMaintenanceGroup` | 创建多时段维护并处理受影响预约 |
| `createRestrictedGroup` | 创建多时段受限规则并触发复审 |
| `setProjectStatus` | 停用/启用课题 |
| `suspendUser` / `restoreUser` | 暂停/恢复账号 |

### 14.7 隐私

| 接口 | 用途 |

### 14.8 业务错误码

至少定义以下稳定错误码，前端不得依赖云函数原始异常字符串：

| 错误码 | 含义 |
| --- | --- |
| `AUTH_REQUIRED` | 当前操作需要已识别账号 |
| `REGISTRATION_REQUIRED` | 未完成注册审核 |
| `ACCOUNT_SUSPENDED` | 账号已暂停 |
| `PROJECT_INACTIVE` | 课题停用或需重新归属 |
| `LEGAL_ACCEPTANCE_REQUIRED` | 必须同意最新协议 |
| `SERVICE_READ_ONLY` | 系统维护或规则迁移中 |
| `INVALID_SEGMENTS` | 时段格式、跨周、过去或越界 |
| `BOOKING_CONFLICT` | 任一时段发生占用冲突 |
| `MAINTENANCE_CONFLICT` | 任一时段命中维护 |
| `DUPLICATE_REQUEST` | 幂等请求已处理 |
| `DUPLICATE_WAITLIST` | 已存在相同时段候补 |
| `STATE_CHANGED` | 记录状态已被其他请求改变 |
| `CONTENT_UNSAFE` | 输入内容未通过安全检测 |
| `PERMISSION_DENIED` | 无权限访问或操作 |

### 14.9 后台任务

后台任务统一使用服务器时间、分布式租约或唯一任务键，保证重复触发不重复处理。任务正文不得依赖某个管理员保持在线。

| 任务 | 触发方式 | 最低职责 |
| --- | --- | --- |
| `expireBookingReviews` | 每 5 分钟 | 将最早时段已开始的待审核单置为超时并释放未来时段 |
| `expireCancelReviews` | 每 5 分钟 | 自动驳回已到开始时间的取消审核 |
| `reconcileWaitlists` | 占用释放事件 + 每 5 分钟兜底 | 校验队首、建立全时段锁、处理确认超时和顺延 |
| `scanSettingsVersion` | 每 1 分钟 + 写接口前检查 | 检测规则版本并启动唯一迁移任务 |
| `processDeletionTasks` | 每 5 分钟 | 分步匿名化、解除关联、重试失败步骤 |
| `syncProjectDisplayCaches` | 课题改名后立即触发 | 分页更新关联显示缓存并校验完整性 |
| `generateDailyStats` | 每日凌晨 | 汇总上一自然日匿名统计 |
| `cleanupRetentionData` | 每日低峰期 | 执行 30/90/365 天保留规则和备份过期清理 |

每个任务至少记录：`status`、`cursor`、`attempts`、`nextRetryAt`、`leaseUntil`、`lastErrorCode`、`createdAt`、`updatedAt`。错误信息只保存分类码和必要技术上下文，不保存姓名、备注或审核正文。

### 14.10 通用接口契约

成功响应统一为：

```js
{
  success: true,
  data: {},
  error: null
}
```

失败响应统一为：

```js
{
  success: false,
  data: null,
  error: {
    code: 'BOOKING_CONFLICT',
    message: '存在不可预约时段'
  }
}
```

- 如需补充 `details`，只能返回帮助当前用户修正操作的非敏感数据。
- 列表接口使用 `cursor + limit`，默认 `20`、最大 `50`，不得用不断增大的页码扫描大集合。
- 时间输入输出统一使用带时区的 ISO 8601 字符串；云函数进入业务层后立即转成服务器时间对象。
- 前端不得展示原始堆栈、数据库错误、函数名或内部记录 ID。
- 写操作中的 `requestId` 是客户端生成的幂等键；对关键占用写操作，服务端还应通过独立互斥锁避免并发双写。

`getPublicCalendar` 最小返回结构：

```js
{
  weekStart,
  serverNow,
  rulesVersion,
  serviceMode,
  maxAdvanceDays,
  slots: [
    {
      startAt,
      endAt,
      state,                 // occupied / pending / maintenance
      projectAbbr,           // 按公开展示矩阵决定是否返回
      publicRenderId
    }
  ]
}
```

`createBookingV2` 成功时只返回新预约的真实 ID、最终状态、预约类型、审核原因和排期键；不得回传其他用户或冲突预约详情。`BOOKING_CONFLICT` 只返回当前用户可修正的非敏感冲突信息，不返回占用者、课题、备注或真实预约 ID。

## 18. 旧数据迁移与上线

### 18.1 迁移策略

- 清除旧用户手机号、学号、学院、导师等资料。
- 所有旧用户恢复为未注册，重新同意协议和注册。
- 取消全部旧未来预约、待审核、取消申请和候补。
- 旧历史预约立即匿名化，仅保留匿名统计字段。
- 迁移前生成加密备份，仅项目负责人可访问。
- 新版验证成功后 7 天内删除备份。

### 18.2 维护窗口

- 设置一次性维护窗口。
- 普通用户只看到只读升级公告页。
- 不重新开放旧版隐私数据结构。
- 迁移失败时保持维护状态，使用备份修复后重新执行。

### 18.3 生产环境验收

本项目已决定直接在生产云环境验收，因此必须：

- 全程保持维护模式。
- 只允许管理员 `openid` 白名单进入测试流程。
- 使用明显虚构姓名和课题。
- 禁止使用真实用户资料测试。
- 验收后按固定白名单清空全部业务集合。
- 保留系统配置、协议版本、匿名历史统计和管理员服务端配置。
- 清理后检查各业务集合记录数、测试身份残留和管理员权限。
- 管理员手动解除维护模式。

### 18.4 故障回退

正式开放后出现以下问题立即进入维护：

- 姓名、`openid`、备注等越权返回
- 冲突或重复预约成功
- 注销、权限鉴权或规则迁移异常
- 大范围无法登录、查看周历或预约
- 数据状态明显不一致

保留新版数据，不回滚到旧个人信息结构。修复后重新验收，由管理员手动开放。

### 18.5 部署与开放顺序

生产环境必须按以下顺序执行，不允许先发布新版前端再补数据库和云函数：

1. 记录当前云函数版本、配置和集合数量，开启维护模式。
2. 部署只读兼容层、服务端鉴权、协议接口和维护页。
3. 创建新集合、索引、任务唯一键和最小权限规则。
4. 执行旧数据备份、个人字段清理、历史匿名化和未来记录终止。
5. 部署 v2 写云函数及后台定时任务，保持普通用户只读。
6. 部署新版小程序前端，仅开放管理员白名单验收。
7. 完成接口权限、并发、弱网、真机 UI 和注销恢复测试。
8. 清除虚构测试数据，核对集合数量、任务状态和管理员角色。
9. 上传体验版/审核版并完成提审资料检查。
10. 审核通过且生产复核完成后，由管理员手动切换为 `normal`。

每一步必须有可观察的完成条件。任一步失败都保持维护状态，从失败步骤幂等重跑，不执行旧数据结构回滚。

## 20. 验收门槛

### 20.1 隐私

- 注册页不出现旧个人字段。
- 游客网络响应中不存在姓名、备注、`openid`、真实预约 ID。
- 普通用户不能通过直接调用获取他人详情。
- 管理员接口在服务端鉴权。
- 注销失败可幂等重试，不产生半注销账号。

### 20.2 预约

- 不连续多选生成一张预约单。
- 任一冲突整单失败。
- 任一特殊时段整单审核。
- 当前小时、过去格和越界格前后端均禁止。
- 并发提交最多一单成功。
- 写请求重试不生成重复预约。
- 两个用户同时提交交叉但不完全相同的多时段集合时，只允许不冲突的完整预约单成功，禁止部分落单。
- 创建维护与创建预约并发时，最终结果不得出现维护范围内仍有效的新预约。

### 20.3 取消和候补

- 整单取消只影响未来有效时段，历史部分保留。
- 12 小时规则以最早未来时段计算。
- 候补只有全部时段同时可用才锁定。
- 超时或放弃后能够原子顺延。
- 同一候补任务重复触发不会产生两张预约或两个有效锁。

### 20.4 规则和维护

- 维护覆盖预约前显示影响范围。
- 受限和工作时间变更触发整单复审。
- 规则迁移失败时系统保持只读暂停。
- 重要变更只提醒一次且详情可追溯。

### 20.5 界面

- 所有页面符合 `style-guide.md`。
- 所有弹窗白底、可关闭、无拖动误导。
- 无图片、插画、装饰图标、渐变和非必要动画。
- 最小屏幕、系统字体放大和底部安全区无溢出。
- 固定表头、时间列、操作栏和底部导航不遮挡内容。
