## 1. 使用说明

本文档将 `v0.0.3` 开发计划拆分为可执行任务清单，按前端、云函数、清理项、联调验收四类组织。

执行原则：

1. 先处理规则收敛和后端口径，再改前端交互。
2. 所有已确认下线的受限时段路径必须成组清理，不保留半生效状态。
3. 每项任务完成后应对照本文档更新自测结果。

## 2. 前端任务

### 2.1 周历页 `miniprogram/pages/calendar/`

- [ ] 管理员态周历展示“课题简称 + 姓名”。
- [ ] 普通用户周历继续保持最小必要展示，不显示姓名。
- [ ] 管理员点击已预约单元格时，跳转到当前预约信息页面。
- [ ] 管理员点击待确认单元格时，跳转到当前审核确认页面。
- [ ] `待确认` 在本版本中仅指预约待审状态。
- [ ] 管理员点击维护单元格时，跳转到当前维护信息页面。
- [ ] 管理员点击空闲可操作格时，进入维护创建流程。

## 5. 联调与自测清单

### 5.1 预约流

- [ ] 当前日期可预约到第 7 个自然日全天。
- [ ] 示例验证：周四可预约到下周四全天。
- [ ] 同课题冲突时返回专门提示。
- [ ] 当前小时和过去时段仍不可预约。
- [ ] 周末和非工作时间仍进入审核。
- [ ] 受限下线后，不再存在受限触发审核。

### 5.2 周历交互

- [ ] 管理员周历可见“课题简称 + 姓名”。
- [ ] 普通用户不可见姓名。
- [ ] 多选模式下不能跨周。
- [ ] 多选模式下翻周按钮禁用并提示。
- [ ] 滑动浏览时不会误触发长按。

### 5.3 维护流

- [ ] 维护创建默认值正确。
- [ ] 时长只能在 `1-12` 小时内选择。
- [ ] 确认信息包含受影响预约数量。
- [ ] 创建维护仅影响未来有效预约。
- [ ] 不会粗暴取消部分已开始预约的整张单。
- [ ] 维护列表仅管理员可见。

### 5.4 后台首页

- [ ] 待办数字可直达处理页。
- [ ] 首页只保留一个“注册用户/课题待审”入口。
- [ ] “取消待审”入口同时承接规则复审。
- [ ] 非待办入口仅剩维护、设置。
- [ ] 受限时段入口已删除。

### 5.5 管理员维护交互

- [ ] 管理员点击已预约格时，直达预约信息页。
- [ ] 管理员点击待确认格时，直达审核确认页。
- [ ] 管理员点击维护格时，直达维护信息页。
- [ ] 管理员点击空闲格时，主操作为维护创建而不是预约。
- [ ] 状态格跳转优先复用现有页面体系，不新建统一“周历详情页”。
- [ ] 周历维护创建弹窗标题为“维护仪器”。
- [ ] 周历维护创建弹窗按钮为“取消”“确认维护”。

### 5.6 用户管理

- [ ] 用户管理页只显示已通过用户。
- [ ] 待审核用户和待审核课题不出现在用户管理页。

## 6. 建议执行顺序

1. 收敛预约与维护规则，先改云函数。
2. 下线受限时段入口和相关接口。
3. 改造周历交互与管理员展示。
4. 改造维护页录入方式与确认弹窗。
5. 改造后台首页待办入口。
6. 联调与回归自测。

---

## 7. 完成定义

满足以下条件后，可视为 `v0.0.3` 开发完成：

1. 文档中列出的本版纳入范围均已有代码实现。
2. 受限时段路径已下线，不再对用户和管理员形成残留入口。
3. 预约、周历、维护三条主链路完成联调验证。
4. 核心交互与文案符合 `development-plan-v0.0.3.md` 中的规范。
