# 微信小程序审核合规优化计划

> **文档状态：合规检查参考。** 本文早于后续完整业务决策，其中注册流程、课题模型、迁移方式、管理员展示和统计范围等细节已由 [`execution-baseline-v2.md`](./execution-baseline-v2.md) 更新。审核条款映射继续有效，具体实现以 v2 执行基线为准。

版本：v1.0

制定日期：2026-06-10

适用项目：仪器预约小程序
主要依据：微信官方《微信小程序平台常见拒绝情形》

官方规范：<https://developers.weixin.qq.com/miniprogram/product/reject.html>

## 1. 优化目标

本次优化以最小必要采集、明确告知、授权同意、分级展示、数据安全和完整可用为原则，解决审核反馈并降低后续复审风险。

核心目标：

1. 注册时只采集课题名称、课题缩写和姓名。
2. 不再采集或保存手机号、邮箱、学号、学院、导师等信息。
3. 注册前必须主动同意《用户服务协议》和《隐私政策》。
4. 游客和普通用户在周历中只能看到课题缩写，管理员才可看到预约人姓名。
5. 过去日期、已开始小时格显示灰色且不可选择，云函数同步阻止提交。
6. 提供退出登录、账号注销和数据删除能力。
7. 用户输入内容经过安全检测，避免违规信息进入页面或数据库。
8. 小程序功能、简介、类目、页面和提审材料保持一致。

## 3. 3.4 用户隐私和数据安全专项计划

### 3.1 明确告知和主动同意，对应 3.4.1

注册页在输入框前提供简短用途说明：

> 为完成实验室使用人员审核、预约身份识别和课题缩写展示，我们仅收集课题名称、课题缩写和姓名。

注册页必须提供未预选的同意控件：

```text
□ 我已阅读并同意《用户服务协议》和《隐私政策》
```

实施要求：

- 默认不勾选。
- 两份协议均可点击进入全文页面。
- 未勾选时提交按钮禁用。
- 前端验证同意状态，云函数再次强制验证。
- 数据库保存同意的协议版本和时间。
- 政策更新时，可依据版本要求用户重新确认。
- 隐私政策明确说明收集目的、使用范围、保存期限、展示对象、删除和注销方式。
- 当内容安全接口不可用时，写入型云函数必须失败返回，不能跳过检查继续写库。

### 3.2 最小必要采集

用户主动填写字段仅为：

| 字段 | 数据库字段 | 必填 | 用途 |
| --- | --- | --- | --- |
| 课题名称 | `projectName` | 是 | 管理员核验所属课题 |
| 课题缩写 | `projectAbbr` | 是 | 周历脱敏展示 |
| 姓名 | `name` | 是 | 管理员审核和内部预约管理 |

不得继续收集或保存：

- 手机号
- 邮箱
- 学号或工号
- 学院
- 导师或负责人
- 微信昵称和头像
- 通讯录、位置、设备敏感信息

`openid` 仅作为微信登录技术标识，由云函数获取，不在页面展示，不向其他用户返回。

### 3.3 禁止收集微信密码，对应 3.4.2

- 不提供微信用户名、微信密码、支付密码或短信验证码输入框。
- 不使用“绑定微信账号”等可能误导用户输入凭据的文案。
- 登录仅通过微信小程序运行环境和云函数获取 `openid`。

### 3.4 禁止小程序搜索功能，对应 3.4.3

- 本项目不提供搜索其他微信小程序、导流或小程序导航功能。
- 用户管理中的搜索仅允许管理员搜索本系统内部课题或用户，不得搜索微信生态账号。

### 3.5 禁止出售、转交和泄露，对应 3.4.4

技术措施：

- 所有数据库写操作必须通过云函数。
- 数据库集合不允许小程序端直接写入。
- 管理员权限必须在云函数中依据 `users.role` 复核，不能只依赖前端隐藏入口。
- 普通用户只能查询自己的完整预约和个人资料。
- 第一版不提供用户资料 Excel 导出。
- 云函数返回数据前执行字段白名单，不直接返回完整数据库记录。
- 预约创建、候补转正等关键冲突写操作必须在服务端串行化，避免并发下产生重叠预约。
- 日志不得输出姓名、`openid`、协议记录或备注全文。
- 生产环境与测试环境分离，测试数据不得使用真实个人资料。

管理措施：

- 隐私政策明确不出售、不交易、不向无关第三方提供数据。
- 管理员仅能因注册审核、预约审核和仪器管理目的查看姓名。
- 管理员页面不展示 `openid`。

### 3.6 未授权不得显示用户数据，对应 3.4.5

周历展示矩阵：

| 访问身份 | 课题缩写 | 姓名 | 备注 |
| --- | --- | --- | --- |
| 未登录用户 | 可见 | 不可见 | 不可见 |
| 普通登录用户 | 可见 | 不可见 | 仅本人预约详情可见 |
| 管理员 | 可见 | 可见 | 管理业务所需时可见 |

禁止在公开周历返回：

- 姓名
- 课题全称
- `openid`
- 预约备注
- 审核意见

管理员姓名展示必须由云函数确认管理员角色后返回。

### 3.7 系统安全与位置，对应 3.4.6、3.4.7

- 不要求用户越狱、ROOT、安装证书或降低系统安全设置。
- 本项目不收集、不追踪地理位置。
- 不申请通讯录、相册、摄像头、麦克风或位置权限。
- 后续若新增权限，必须先更新隐私政策、公众平台隐私保护指引和用户授权流程。

### 3.8 退出登录和账号注销

“我的”页面新增“账号与隐私”区域：

- 《用户服务协议》
- 《隐私政策》
- 查看个人资料
- 退出登录
- 注销账号

退出登录：

- 清除小程序本地用户状态和缓存。
- 返回游客状态。
- 不等同于删除账号。

注销账号：

1. 明确提示注销后果。
2. 用户二次确认。
3. 取消未来预约及候补记录。
4. 删除 `users` 中的个人资料和协议记录。
5. 删除通知记录。
6. 删除或不可逆匿名化历史预约中的 `userId`、`openid`、姓名等关联信息。
7. 审核日志仅在确有管理必要时保留匿名记录，不保留可识别身份字段。
8. 注销完成后回到游客状态。

## 4. 数据模型重构

### 4.1 `users`

```js
{
  _id,
  openid,
  role,
  registrationStatus,
  projectName,
  projectAbbr,
  name,
  agreementVersion,
  agreementAcceptedAt,
  privacyVersion,
  privacyAcceptedAt,
  rejectReason,
  reviewedBy,
  reviewedAt,
  createdAt,
  updatedAt,
  lastLoginAt
}
```

移除字段：

```text
phone
email
studentId
college
supervisor
```

### 4.2 `bookings`

为减少个人信息冗余，建议改为：

```js
{
  _id,
  userId,
  projectAbbrSnapshot,
  startAt,
  endAt,
  occupiedSegments,
  durationHours,
  remark,
  status,
  bookingType,
  specialReasons,
  reviewReason,
  reviewedBy,
  reviewedAt,
  createdAt,
  updatedAt
}
```

不再冗余保存：

- `openid`
- `userName`
- `college`

管理员查询预约时，由云函数使用 `userId` 查询用户姓名。周历普通查询只返回 `projectAbbrSnapshot`。

### 4.3 `waitlists`

- 使用 `userId` 关联用户，不冗余保存姓名、学院和 `openid`。
- 候补转正时写入 `projectAbbrSnapshot`。
- 注销账号时删除该用户全部候补记录。

### 4.4 协议版本

在代码配置中定义：

```js
const LEGAL_VERSIONS = {
  serviceAgreement: '1.0',
  privacyPolicy: '1.0'
}
```

注册云函数只接受后端当前版本，不信任前端自行传入任意版本。

## 6. 周历隐私与过去时段

### 6.1 身份脱敏

`getCalendarBookings` 返回字段必须按身份白名单生成：

普通返回：

```js
{
  bookingId,
  status,
  startAt,
  endAt,
  projectAbbr
}
```

管理员额外返回：

```js
{
  userName
}
```

周历格显示：

- 主文字：课题缩写。
- 管理员副文字：姓名。
- 普通用户和游客不显示姓名。

### 6.2 过去时段判定

统一使用中国标准时间，并按整点判断：

```text
minimumStartAt = 当前时间向上取整到下一个整点
cellStartAt < minimumStartAt => 已过去或已开始
```

例如当前为 10:20：

- 10:00-11:00 显示灰色且不可预约。
- 11:00-12:00 可以预约。

前端要求：

- 增加 `calendar-cell--past` 灰色样式。
- 已过去格显示“已结束”或不显示文字。
- 点击、长按、多选均忽略过去格。
- 多选确认前再次检查选区。

后端要求：

- `createBooking` 强制校验 `startAt >= minimumStartAt`。
- `joinWaitlist` 同步禁止过去时段。
- 前端时间不能作为可信依据，必须使用云函数服务器时间复核。

## 7. 用户输入内容安全

需要检查的输入：

- 课题名称
- 课题缩写
- 姓名
- 预约备注
- 注册拒绝说明
- 预约拒绝说明
- 取消说明
- 维护原因
- 受限时段说明

处理流程：

1. 前端限制长度并清理首尾空格。
2. 云函数执行长度、格式和空内容校验。
3. 云函数调用微信文本内容安全检测能力。
4. 检测不通过时不写入数据库，返回清晰提示。
5. 不在日志中打印完整输入内容。

课题缩写建议限制为中文、英文字母、数字、连字符和下划线，长度 1-20 字符。

## 8. 旧数据迁移与删除

迁移前先导出数据库备份，仅用于迁移回滚，完成后按约定期限删除备份。

迁移步骤：

1. 为现有用户增加 `profileUpdateRequired: true`。
2. 删除 `phone`、`email`、`studentId`、`college`、`supervisor`。
3. 已审核用户暂时保留审核状态，但预约前必须补充课题名称、课题缩写并同意协议。
4. 管理员账号先人工补充新字段，避免管理入口不可用。
5. 从预约、候补记录删除 `college` 和冗余 `openid`。
6. 用户补充新资料后，为仍需展示的预约回填 `projectAbbrSnapshot`。
7. 无法归属课题缩写的历史预约统一显示“历史预约”，不得回显姓名。
8. 迁移脚本输出数量统计，不输出具体个人资料。

## 10. 数据库权限与安全

- 所有集合禁止客户端直接写入。
- `users`、`bookings`、`waitlists`、`review_logs` 和 `notifications` 不允许客户端直接读取完整记录。
- 周历、个人记录和管理数据均通过云函数返回字段白名单。
- 云函数所有管理员接口必须服务端鉴权。
- 索引仅包含业务查询需要字段，避免建立个人资料检索索引。
- 删除不再使用的旧示例云函数，减少攻击面。
- 生产云环境不保留测试管理员或通用弱权限账号。

## 11. 提审前测试矩阵

### 11.1 游客

- 无需登录即可查看周历。
- 只能看到课题缩写和占用状态。
- 看不到姓名、备注、`openid`。
- 过去时段不可点击或长按。

### 11.2 未注册用户

- 可打开协议和隐私政策。
- 未同意协议不能提交。
- 只能填写三项资料。
- 不出现手机号、邮箱、学号、学院或导师字段。

### 11.3 已审核普通用户

- 可预约未来整点时段。
- 只能看到其他预约的课题缩写。
- 可查看自己的备注和审核结果。
- 可退出登录、查看协议、申请注销。

### 11.4 管理员

- 注册、预约和取消审核可正常完成。
- 仅管理员可看到预约人姓名。
- 看不到已删除的手机号、学号等字段。
- 管理接口无法被普通用户通过直接调用绕过。

### 11.5 注销账号

- 有明确后果说明和二次确认。
- 注销后不能访问原个人资料。
- 数据库中不再存在可识别的关联个人资料。
- 再次进入时视为新用户。

### 11.6 完整性和 UI

- 所有按钮有响应且不超出屏幕。
- 所有弹窗白底并可关闭。
- 无测试、演示、占位或无效入口。
- 真机测试小屏设备、深色系统环境和弱网情况。
